7개 위젯, 하나의 셸

각 기능은 원초적 고민(Q1~Q8) 중 하나에 대한 구체적인 답이다. 표시된 태그를 따라가면 "왜 이걸 만들었는지"로 이어진다.

Q1 · Q2

Daily Brief 에이전트

Python 에이전트가 매일 아침 07:30 메일·일정·할일을 모아 Claude로 요약하고, 브리핑을 Notion에도 남긴다. 사람이 우선순위를 매번 짜지 않아도 된다.

Q3

칸반 + 단일 완료

한 곳에서 체크하면 모든 뷰가 따라온다. 단일 클라이언트 캐시로 리스트·보드가 항상 같은 상태를 본다.

Q4

자동 태그 분류

에이전트는 태그 없는 할 일만 채운다. 사용자가 한 번이라도 손댄 태그는 절대 건드리지 않는다.

Q4

OKR · 주간 플래너

지난주·이번주·다음주 버킷과 KR 진행률을 순수 SQL 집계로 계산해 라인차트로 보여준다.

Q5

에이전트 활동 위젯

sync·분류·브리핑이 언제 돌았는지 항상 보인다. "지금 실행" 버튼으로 즉시 트리거도 가능.

Q6

위젯 셸

창처럼 옮기고 늘이고, 위젯마다 테마를 다르게 입히고, 레이아웃은 그대로 저장된다.

Q7

진행 현황 · 파일 탐색

저장소를 열지 않고도 앱 안에서 프로젝트 구조와 진행 문서를 그대로 읽는다.

결정 하나, ADR 파일 하나

아직 감당 못 하는 지점도 남긴다

역 계획서는 "만들었지만 다시 봐야 할 것"도 정면으로 적는다. 대부분 로컬 단일 사용자·1인 개발·마감이라는 같은 원인에서 나왔고, 다중 사용자·패키징 배포로 가면 되짚을 항목이다.

S1
백엔드가 로컬 네트워크에 열려 있다인증 없이 전 인터페이스 바인딩 — 같은 Wi-Fi 기기가 데이터를 CRUD 할 수 있다
S2
CORS가 Origin: null을 모든 빌드에 허용패키징 앱의 file:// 로딩용 예외가 데모·개발 빌드까지 상속됐다
S3
태그 비침범이 트리거가 아닌 코드로만 지켜진다값 자체는 DB CHECK로 강제되지만, 행 단위 불변식은 애플리케이션 층 책임
S4
OAuth 토큰 키에 회전 절차가 없다키 1개가 Gmail·Calendar 읽기 토큰 전부를 푼다
D1
웹 데모 패리티가 "경로 존재"까지만 자동화응답 스키마·상태코드 드리프트는 아직 CI가 못 잡는다
D2
REST 오류가 단일 봉투다클라이언트가 오류 종류를 코드로 구분하지 못한다 — RFC 9457 제안 중

파일 트리·문서 경로만은 예외다 — 심링크 스킵·이중 인코딩 우회 차단·상한까지, 같은 마감 압박 아래서도 미루지 않았다.
