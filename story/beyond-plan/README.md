# 🚀 계획보다 더 나아간 것들 — 원래 문서에 없던 기능들

`VISION.md`·`PERSONAL_OS.md`가 처음 그렸던 그림에는 없었는데, 만들면서 생긴 기능들이다.
셋 다 "기능이 먼저"가 아니라 **사용자가 실제로 말한 구체적인 불편**에서 나왔다는
공통점이 있다.

---

## 1. 기대정렬 체크인 — 나 자신을 향한 방법론

**계획에 없던 이유:** 원래 문서(ADR)는 전부 **프로젝트를 향한** 결정 기록이었다.
"나 자신에게 반복 적용하는 자기 점검 방법론"은 어느 요구사항 문서에도 없었다.

**왜 생겼나:** 사용자가 이미 비공식적으로 1주차(프로토타입)·2주차(역량 피드백 수용)·
3주차(기획서 작성)처럼 스스로에게 7가지 질문(뭘·왜·언제까지·목표·전략·구체적으로·
상태)을 반복하고 있었는데, 그게 어디에도 기록되지 않고 기억에만 있었다. "프로젝트를
향한 방법론이 ADR이라면, 나 자신을 향한 방법론이 기대정렬"이라는 문장으로 이 기능이
시작됐다(ADR-0035).

**계획보다 더 나아간 지점:** 단순 기록 기능으로 끝나지 않고, 이 답변이 나중에
프로젝트의 OKR을 만드는 **기초 데이터**가 되는 구조로 확장됐다(§changes/2 참고) —
자기 점검이 프로젝트 추적의 출발점이 되는 순환이 생겼다.

## 2. 지식 축적 추세·역량 지도 뷰 — 목적 재정의가 낳은 기능

**계획에 없던 이유:** P0~P9 로드맵 어디에도 "지식이 쌓이는 추세를 보여주는 뷰"는
없었다. 이건 애초에 §1-0 목적 재정의(2026-09-14)가 있고 나서야 존재할 수 있는
기능이었다.

**왜 생겼나:** 목적을 "진척률이 아니라 지식"으로 다시 정의한 뒤, 지금까지 만든
기능을 전부 그 기준으로 재검토했다(§5-3 정합성 감사). 결과: 강함 2·보통 2·인프라
3(정상)·약함 2·**공백 2** — 그중 하나가 "지식 축적 추세·역량 지도"였다. 기대정렬
체크인·OKR 데이터는 이미 있는데, 그걸 시계열로 종합해서 "역량이 어느 방향으로
크는지" 보여주는 화면이 없다는 게 감사에서 드러났다.

**계획보다 더 나아간 지점:** 기존 데이터(체크인 빈도·OKR 달성률·태그 분포)를
새 테이블 하나 없이 순수 SQL 집계로만 종합했다 — "필요하니까 데이터를 새로 쌓자"가
아니라 "이미 쌓인 걸 처음으로 연결해서 보여주자"는 방향으로, 목적 재정의가 실제
기능 설계 방식까지 바꾼 사례다.

## 3. GitHub 연동 (방향) — "작업물이 어디 있는지"

**계획에 없던 이유:** 원래 앱은 프로젝트 진행 상태만 다뤘다 — 그 진행이 실제로
어느 저장소, 어느 커�밋에 있는지는 범위 밖이었다.

**왜 생겼나:** "그리고 깃허브와 작업하는걸 연동해서 내가 작업물이 어디에 있는지까지
확인하는게 목적이구"라는 요청에서 시작됐다. 지식(기대정렬·OKR)만 보여주고 실제
결과물의 위치를 안 보여주면 반쪽짜리라는 지적이었다.

**계획보다 더 나아간 지점:** 아직 방향 목업 단계지만, 프로젝트 카드 안에 GitHub
최근 커밋을 나란히 두는 구조로 — "지식이 어디서 실물이 됐는지"까지 한 화면에서
확인하는 흐름으로 설계 방향이 잡혔다.
