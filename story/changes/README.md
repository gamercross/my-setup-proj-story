# 🔄 무엇이 바뀌었나 — 처음 계획 대비 달라진 것들

처음 세운 계획이 끝까지 그대로 간 적은 없다. 여기 모은 것은 "실수"가 아니라
**더 붙잡아 본 뒤에야 보인 것들**이다 — 바뀐 순서대로 정리한다.

---

## 1. 목적 자체가 바뀌었다 — "진척이 안 보인다" → "지식이 안 쌓인다"

- **원래(2026-09-09):** "내가 뭐가 진척되는지 감이 안 와서." 이 문장을 붙잡고 설계를 시작했다.
  프로젝트·강의·삶 세 영역에서 "얼마나 왔는지"가 안 보이는 게 문제라고 생각했다.
- **바뀐 것(2026-09-14):** 사용자가 직접 다시 정의했다 — "우리의 목적은 진척도를
  보는 것이 아닌, 자신의 프로젝트나 경험들이 모인 지식을 시각화하고 도식화해서
  지식 가치를 올리는 것." 진척률은 증상이었지 목적이 아니었다.
- **왜 바뀌었나:** OKR·주간 플래너 같은 "진척률 보여주기" 기능을 만들고 나서도
  뭔가 허전했다. 실제로 원한 건 숫자가 아니라 — "무엇을 배웠는지"가 쌓여 보이는
  자리였다. 이 재정의 이후 모든 기존 기능을 §5-3 감사로 다시 검토했다.

## 2. OKR — 단독 화면이었다가, 프로젝트 안으로 들어갔다

- **원래(P8, 2026-09-08):** OKR을 `objectives`/`key_results`/`kr_snapshots` 3테이블의
  1급 엔티티로 만들고, 전용 대시보드 화면을 뒀다. 구글식 등급(committed/aspirational)까지
  붙였다(ADR-0034).
- **바뀐 것(2026-09-15):** "프로젝트를 담당할 때 OKR이 따로 있는 게 아니라 프로젝트
  안에 있어야 한다"는 지적을 받고 OKR 단독 화면을 없앴다. 이제 OKR은 프로젝트 카드
  하나 안에서 — 기대정렬 답변(시작 근거) → Objective·KR(진행) → GitHub 최근 커밋
  (작업물 위치) 순서로만 존재한다.
- **왜 바뀌었나:** OKR을 프로젝트와 분리해 두니 "이 숫자가 무슨 프로젝트 얘기인지"를
  매번 다시 찾아야 했다. 지식(기대정렬)과 그 지식이 낳은 추적(OKR)을 한 화면에
  묶으니 그제서야 "이 프로젝트가 지금 뭘 하고 있는지"가 한눈에 들어왔다.

## 3. 할 일 분류 — 고정 카테고리였다가, 자유 태그 + 출처 구분으로

- **원래 고민(PO-3):** "분류 체계를 고정 집합으로 둘까, 자유 태그로 둘까."
- **진짜 문제였던 것:** "에이전트가 내가 달아 둔 태그를 침범하면 어쩌지." 자동화가
  사용자 의도를 조용히 훼손하는 걸 피하는 게 진짜 걱정이었다.
- **바뀐 것:** 자유 태그(다중) + `source ∈ {user, agent}` 출처 구분으로 확정.
  에이전트는 `source='user'` 태그가 붙은 할 일을 절대 건드리지 않는다.

## 4. 위젯 커스터마이즈 — 크게 투자했다가, 우선순위를 낮췄다

- **원래:** 위젯별 테마·표시 옵션(C6)에 상당한 공수를 들였다 — 강의 A("AI 컴퓨터
  운영체제 실습")의 창·프로세스·레이아웃 관리 주제와 겹쳐서였다.
- **바뀐 것(§5-2 재검토):** "실제로 쓰면 가장 갈망할 기능"을 물었을 때 위젯
  커스터마이즈는 목록에 없었다. 인프라(화이트리스트·자동 폼)는 남기되, 위젯별
  색·모서리 커스터마이즈에 더는 시간을 쓰지 않기로 했다 — 제품 필요와 강의 필요가
  겹친 지점이라 투자했지만, 사용자 갈망과는 어긋났다는 걸 인정한 기록.
